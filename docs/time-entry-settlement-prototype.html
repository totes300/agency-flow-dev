Phase 8 PRD · Visual Verification

Time Entry Settlement

How each project type closes its time entries, what the user sees, and what gets written to the database. Four scenarios, four billing realities, one consistent model.

Status badges — what entries look like

Open
Needs attention. Billable hour, not yet on an invoice or in a closed period.
Draft
On a draft invoice. Read-only until the invoice is finalized or the draft is dropped.
Closed
Done — invoiced, or covered by the retainer fee / fixed price. No longer needs attention.
One pill = one fact. The row badge is just the lifecycle (Open / Draft / Closed). Whether a closed hour earned revenue (invoiced) or was covered by the retainer/fixed deal lives in the Amount column and reports — not on every row. The schema still records the precise reason (settledReason) for those reports.
Status lexicon — same words, every surface NEW · #3
Lifecycle stage Time entry Period (month) Invoice doc
Accruing / editable Open In progress Draft
Claimed, awaiting finalize Draft Open (ended) Draft
Done / locked Closed Closed Invoiced / Paid

The Invoices tab keeps its document-native words (Draft → Invoiced → Paid → Void) because that's a financial document lifecycle. But "Open / Closed" mean the same thing everywhere else, and "Closed" never collides — a closed period whose overage is on a Paid invoice reads consistently: the period is Closed, the invoice is Paid, the hours are Closed.

One CTA per row + ⋯. Every row ends with one primary button and one overflow menu — clean vertical rhythm.
#2 — Status reflects whether you must act. In progress (hollow, faint) = current month, nothing to do — the eye skips it. Open (blue) = ended, needs your action — paired with the dark button. Closed (grey) = done. No longer two meanings on one "Open".
#1 — "Close" opens the statement to review, then confirms (Stripe finalize pattern) — so Preview isn't a separate item on closable rows; it's the first step of Close. Standalone Preview stays only on the current month.
#6 — "Billed here" (not "Amount") = overage billed through this tool. The retainer fee is charged separately via Stripe, so this column never double-counts it.
